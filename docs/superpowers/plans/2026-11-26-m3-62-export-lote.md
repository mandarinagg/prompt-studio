# #62 Export, cola y lote — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Exportar varias fotos a la vez a una carpeta recordada por proyecto, ver y manejar los exports en una cola (cajón), y editar en lote: "Pedido para N", copiar/pegar ajustes y Ctrl+Z que deshace el lote en la biblioteca.

**Architecture:**
- **Engine:** casi todo existe (`job.export` con N fotos y `out_dir`, nombres sin pisar, `group_id` en el historial, `asset.undo_group`). Faltan: la carpeta de export **recordada** en `project.json` (`Project.export_dir`, hoy sin uso) y expuesta en `ProjectInfo`; dos métodos de lote atómicos (`asset.apply_plan_many`, `asset.paste`) que validan todo antes de tocar nada, generan el `group_id` y guardan **una** vez; CLI equivalente.
- **App:** el diálogo de export recibe una lista de fotos y se cierra al confirmar (diseño §7: "el progreso queda en la cola"); un cajón `QueueDrawer` muestra todos los jobs; un store `batch` (pedido para N, portapapeles de ajustes, último lote para Ctrl+Z) consumido por la barra de selección y dos diálogos. "Abrir carpeta" es un comando Rust que solo abre carpetas que el engine informó como destino de un job.

**Tech Stack:** Python 3.14 + Pydantic (engine), React 19 + TS + zustand vanilla, `@tauri-apps/plugin-dialog` (ya instalado), Rust (Tauri 2), vitest, pytest, cargo test.

**Spec:** `docs/superpowers/specs/2026-11-19-m3-app-escritorio-design.md` §5 (Historial: lotes con `group_id`; pila: geometría = `crop`, `rotate`, `straighten`), §7 (Biblioteca: barra de selección; Exportar; Cola; Lote; Atajos; Accesibilidad).

- "Copiar/Pegar ajustes copia la pila completa, **sin la geometría salvo que se pida**". "En lote se muestra solo el cambio" (sin "→ resultado" en las filas del plan).

## Review Focus
1. **Lote con fotos que cambiaron después:** aplicar un pedido a 3 fotos, editar una en el editor, volver y Ctrl+Z → se deshace en 2 y un aviso dice que 1 cambió y quedó como estaba (T1 `test_undo_group_after_edit`, T4 `undoLast reports skipped`).
2. **Selección con faltantes:** el pedido se planifica sobre la primera seleccionada que **no** falta (si todas faltan, el botón está deshabilitado con motivo); el export las excluye y lo dice ("1 no se encuentra y no se va a exportar"); pegar y aplicar sí funcionan (es solo la pila) (T2, T3 tests).
3. **Carpeta destino:** la elegida se recuerda al cerrar y reabrir el proyecto; una ruta relativa se rechaza con mensaje legible; una carpeta que no se puede crear termina en `job.failed` legible en la cola, no en un cuelgue (T1, T2 tests).
4. **Lote atómico:** un id desconocido en `asset.apply_plan_many`/`asset.paste` no cambia ninguna foto ni escribe `project.json`; sin cambios reales no hay `group_id` y Ctrl+Z no "deshace" nada fantasma (T1 tests).
5. **Cola y reinicio del motor:** con jobs corriendo, si el motor se reinicia la cola los marca fallidos (ya existe `onEngineLost`) y "Abrir carpeta" de un job terminado sigue andando; "Abrir carpeta" con una ruta que no vino de un job se rechaza; si la carpeta se borró, toast legible (T2 tests, Rust test).
