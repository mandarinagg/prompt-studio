# #61 Biblioteca — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** La pantalla del proyecto pasa de lista a **biblioteca**: cuadrícula con miniaturas generadas en segundo plano, marcas de editada y de falta el archivo con "Ubicar…", importar con botón (fotos o carpeta) además de arrastrar, selección múltiple con barra inferior, y una tira de fotos en el editor.

**Architecture:**
- **Engine:** las miniaturas ya existen (`thumbnail.get` + evento `thumbnail.ready`, hilo propio en `rpc/media.py`). Cambio: la miniatura refleja la **pila guardada** (clave = `sha256` del original + huella de la pila), así una foto editada se ve editada en la cuadrícula. Las miniaturas siguen en su hilo liviano, **no** en la cola de jobs de #60: una miniatura no debe esperar detrás de un export de minutos y no es algo que el usuario cancele (ruling; el diseño dice "job" en sentido de segundo plano).
- **App:** un store `library` (lógica pura testeable: selección, foco, URLs de miniaturas con carga perezosa e invalidación) + componentes `LibraryGrid`, `SelectionBar`, `Filmstrip`. `ProjectScreen` usa la cuadrícula; `EditorScreen` la tira.

**Tech Stack:** Python 3.14 + pyvips (engine), React 19 + TS + zustand vanilla + `@tauri-apps/plugin-dialog` (ya instalado, `dialog:allow-open` ya habilitado), vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-11-19-m3-app-escritorio-design.md` §7 (Biblioteca, Editor: tira de fotos, Atajos, Accesibilidad), §5 (faltantes: "Ubicar…" acepta el archivo solo si el hash coincide).

## Global Constraints
- CLAUDE.md: las fotos se **referencian**, no se copian; nunca se escribe sobre originales. Ningún medio sale del equipo. Sin dependencias nuevas (ni npm ni Python ni Rust).
- Contrato: Pydantic → `uv run pstudio schema --rpc --out schema/rpc-1.schema.json` → `pnpm gen:types`. Nada se tipa a mano en dos lados.
- Las imágenes de caché se leen con `cacheImage` (comando Rust `read_cache`, solo dentro de la caché del proyecto) → blob URL; liberar los blob URLs que ya no se usan (`URL.revokeObjectURL`).
- UI en español, palabras simples; código en inglés. Estados nunca solo por color (ícono + texto). Foco siempre visible; todo con teclado.
- No tocar la app mientras corre `pnpm tauri dev` (lo corre el usuario al final). Nunca input sintético.
- Un commit por tarea; mensajes en español como los del repo; terminan con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Fuera de alcance (#62): pedido para N fotos, copiar/pegar ajustes, exportar varias desde la barra, cola visible. La barra de selección de #61 deja el lugar listo pero no implementa esas acciones (ruling: un botón que no hace nada sería peor que no tenerlo).

## Review Focus
1. **Miniatura y pila:** editar una foto (slider, plan, undo) y volver a la biblioteca muestra la miniatura nueva, no la vieja; la miniatura vieja de esa foto se borra de `cache/thumbs/` (no crece sin límite); dos fotos con el mismo original nunca se pisan.
2. **Carga perezosa y orden:** con 200+ fotos solo se piden las miniaturas visibles (o cerca); un `thumbnail.ready` que llega para una foto que ya no está (proyecto cerrado, otro proyecto, engine reiniciado) se ignora y no filtra blob URLs.
3. **Selección:** clic selecciona una, Ctrl+clic suma/quita, Shift+clic rango desde la última ancla, Ctrl+A todas, Esc limpia; las faltantes se pueden seleccionar pero no abrir; la selección sobrevive a importar más fotos y se limpia de ids que ya no existen.
4. **Ubicar…:** elegir un archivo con otro contenido da el error legible del engine y no cambia nada; con el correcto la foto deja de figurar como faltante y su miniatura aparece.
5. **Teclado y accesibilidad:** la cuadrícula es un `role="grid"`/`listbox` con flechas (incluida ↑/↓ por fila según las columnas visibles), Enter abre, Espacio selecciona; cada miniatura tiene nombre accesible con el nombre de archivo y su estado ("editada", "no se encuentra"); la tira del editor no roba ←/→ al visor.

### Task 1: Engine — miniatura de la pila guardada

**Files:**
- Modify: `engine/src/pstudio/rpc/media.py` (`thumb_path`, `thumbnail`, `_run`), `engine/src/pstudio/rpc/methods_media.py` (`thumbnail.get` sin cambios de params salvo que haga falta)
- Test: el archivo de tests que ya cubre `thumbnail.get`/`thumbnail.ready` (buscar en `engine/tests/`)

**Interfaces (produce):**
- `thumb_path(cache_dir, asset)` → `cache/thumbs/<sha256>-<huella>.jpg`, con `huella` = primeros 12 hex de sha256 del JSON canónico de `asset.stack` (pila vacía → huella fija, p. ej. `orig`). Una función pura `stack_digest(stack: EditPlan) -> str` reutilizable.
- Generar: si la pila está vacía, igual que hoy (`pyvips.Image.thumbnail` con shrink-on-load). Si no, usar el mismo camino de render que la preview (proxy chico + `render_preview` o `apply_plan` con `scale`) a `THUMB_SIZE` de lado largo, para que la miniatura coincida con lo que se ve en el editor (recorte y rotación incluidos).
- Al generar una nueva miniatura de una foto, borrar las otras `cache/thumbs/<sha256>-*.jpg` de **esa** foto solo si ningún otro asset del proyecto usa ese mismo `sha256` con esa huella (dos assets pueden compartir original: ver `project.import` duplicados; si el proyecto no admite duplicados, documentarlo y simplificar).
- `ThumbnailReady` sin cambios de forma. La app vuelve a pedir `thumbnail.get` cuando la foto cambia (`edited`/pila) y recibe la ruta nueva o `null` + evento.
- [ ] Medir y anotar en el commit: ms de una miniatura de 45 MP sin pila y con una pila típica (exposición + vibrancia + recorte), en `tests/fixtures/photos` si están.
- [ ] Tests primero: misma foto con pila distinta → ruta distinta; editar y pedir de nuevo → archivo nuevo, el viejo borrado; pila vacía conserva el camino rápido; recorte 1:1 → miniatura cuadrada; falta el archivo → `thumbnail.ready` con `error`; hash del original intacto. Verlos fallar, implementar, `uv run pytest`, ruff. Commit.
