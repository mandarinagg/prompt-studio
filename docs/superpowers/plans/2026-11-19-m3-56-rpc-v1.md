# RPC v1 (#56) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** la app puede abrir/crear un proyecto, importar, pedir un plan, editar la pila con
undo/redo, ver la preview y las miniaturas, todo por RPC tipado, con eventos y relanzamiento
del engine.

**Architecture:** `pstudio.rpc` pasa a ser un paquete:
- un registro de métodos con modelos Pydantic de entrada/salida (validación + JSON Schema);
- una `Session` con el proyecto abierto, proxies y la `PreviewCache`;
- un `Notifier` que escribe respuestas y notificaciones con un lock (el worker de miniaturas
  emite desde otro hilo).

Rust reenvía las notificaciones como evento Tauri `engine-event` y relanza el engine si muere.
La preview se lee con `read_cache`, que solo acepta archivos de la caché del proyecto abierto
(cambio respecto del plan inicial, que usaba el protocolo de assets; ver ADR-0010). Los tipos TS se generan
desde `engine/schema/rpc-1.schema.json`.

**Tech Stack:** Python 3.14 + Pydantic + pyvips; Rust/Tauri 2 (`protocol-asset`); TS +
`json-schema-to-typescript` (dev).

**Spec:** `docs/superpowers/specs/2026-11-19-m3-app-escritorio-design.md` §5, §6, §8;
ADR-0009.

## Global Constraints
- stdout del engine es solo protocolo; errores al usuario en español, sin rutas completas ajenas
  al proyecto ni trazas.
- La preview y las miniaturas se escriben solo en `<proyecto>/cache/`; nunca junto al original.
- El proveedor `cloud` no se expone por RPC hasta que exista el consentimiento (#64).
- Nada se tipa a mano en dos lados: los payloads RPC salen del JSON Schema generado.
- Dependencias nuevas: `json-schema-to-typescript` (dev, aprobada en el diseño §9) y la feature
  `protocol-asset` de Tauri. Nada más.

## Review Focus
1. El proyecto se modifica desde la terminal con la app abierta → la app no pisa esos cambios
   en silencio (error claro y recarga).
2. Un `stack` inválido por RPC (op inexistente, valores fuera de rango) → `INVALID_PARAMS`, el
   engine sigue vivo.
3. La foto se movió → preview y miniatura informan "falta el archivo", sin traza.
4. Muchas previews seguidas de la misma foto → `cache/preview` no crece sin límite.
5. Método llamado sin proyecto abierto → error "no hay un proyecto abierto".

### Task 1: núcleo RPC tipado (paquete `pstudio.rpc`)

**Files:** Create `engine/src/pstudio/rpc/{__init__,server,contract}.py`; delete
`engine/src/pstudio/rpc.py`; Test `engine/tests/test_rpc.py` (los tests actuales siguen
pasando) + `engine/tests/test_rpc_server.py`.

**Interfaces — Produces:**
- `server.method(name: str)`: decorador que registra una función
  `fn(session: Session, params: P) -> R`, donde `P` es un `BaseModel` (o se omite el
  parámetro si no hay params) y `R` es cualquier tipo que Pydantic pueda serializar. Los
  modelos de params usan `extra="forbid"`.
- `server.METHODS: dict[str, Method]`, donde `Method` tiene `name`, `params: type[BaseModel]`,
  `result: Any` y `fn`.
- `server.EVENTS: dict[str, type[BaseModel]]`.
- `handle_line(line, session=None) -> dict | None`.
- `serve(stdin=None, stdout=None)`.
- `Notifier(out)` con `send(obj)` y `emit(event, payload: BaseModel)`, protegido por lock.
- `RpcError(code, message)`; constantes de error + `NO_PROJECT = -32001`.

**Tests:**
- `test_params_validated_by_model`: los params extra o con tipo incorrecto dan
  `INVALID_PARAMS`, y el mensaje nombra el campo.
- `test_emit_writes_notification_without_id`.
- `test_notifier_is_thread_safe`: 8 hilos × 50 emits dan 400 líneas JSON válidas.

### Task 2: sesión, `project.*` y `asset.*`

**Files:** Create `engine/src/pstudio/rpc/session.py` y
`engine/src/pstudio/rpc/methods_project.py`; Test `engine/tests/test_rpc_project.py`.

**Interfaces — Consumes:** `store.create/open_project/save/add_assets/relink/missing`,
`history.push/undo/redo/jump/undo_group`, `stack.merge`.

**Produces:**
- `Session`: `project`, `path`, `require() -> Project`, y `commit()`. `commit()` guarda, pero
  antes verifica que `project.json` no cambió en disco desde que se cargó (mtime_ns + size).
  Si cambió, recarga, levanta `RpcError(PROJECT_CHANGED, "el proyecto cambió fuera de la app:
  se recargó, repetí la acción")` y no escribe.
- Métodos:
  - `project.create {dir,name}` y `project.open {path}` devuelven `ProjectInfo`
    `{path, name, cache_dir, assets: AssetSummary[]}`.
  - `project.info` devuelve `ProjectInfo`.
  - `project.import {paths, recursive}` devuelve `ImportResult`
    `{added: AssetSummary[], duplicates, unsupported: str[]}`.
  - `project.relink {asset, path}` devuelve `AssetSummary`.
  - `asset.state {asset}` devuelve `StackState`
    `{asset, stack, cursor, label, can_undo, can_redo, changed}`.
  - `asset.history {asset}` devuelve `{cursor, entries: {label, group_id, at}[]}`.
  - `asset.set_stack {asset, stack, label, group_id?}`, `asset.apply_plan
    {asset, plan, label?, group_id?}` (agrega `export_hint`), `asset.undo`, `asset.redo`,
    `asset.jump {asset,index}` y `asset.reset` devuelven `StackState`.
  - `asset.undo_group {group_id}` devuelve `{undone: str[], skipped: str[]}`.
  - `AssetSummary` es `{id, file, edited, missing}`. Las rutas absolutas solo van en
    `ProjectInfo.path/cache_dir`.

**Tests:**
- Recorrido create → import (2 fotos + duplicado) → apply_plan → undo → redo → reset.
  `project.json` refleja cada paso.
- Sin proyecto abierto, `asset.state` da `NO_PROJECT`.
- `test_external_change_is_not_overwritten` (Review Focus 1).
- Un `stack` con `{"op":"exec"}` da `INVALID_PARAMS`.
- Un asset inexistente da `ENGINE_ERROR` "no existe la foto".

### Task 3: `plan.create`, `preview.render`, `thumbnail.get`

**Files:** Create `engine/src/pstudio/rpc/methods_media.py`; Modify `session.py` (proxies y
worker de miniaturas); Test `engine/tests/test_rpc_media.py`.

**Produces:**
- `plan.create {prompt, asset?, provider: "auto"|"rules"|"local_llm" = "auto"}` devuelve
  `{plan, provider, ms, warnings, errors, draft, export_hint}`, donde
  `draft = merge(asset.stack, plan).stack` si viene `asset`.
- `preview.render {asset, stack?, long_side: 256..2048 = 2048}` devuelve
  `{path, width, height, render_ms, encode_ms}`:
  - el proxy se cachea por `(asset, sha256, long_side)` en un LRU de 4;
  - el resultado es un JPEG Q85 en `cache/preview/<asset>-<n>.jpg`;
  - el archivo anterior de ese asset se borra (Review Focus 4);
  - `cache/preview` se vacía al abrir el proyecto.
- `thumbnail.get {asset}` devuelve `{asset, path|null}`:
  - si `cache/thumbs/<sha>.jpg` existe, lo devuelve;
  - si no, lo encola en un hilo worker (sin duplicados) y después emite `thumbnail.ready
    {asset, path|null, error|null}`;
  - la miniatura tiene lado largo 320 y se escribe con tmp + replace.

**Tests:**
- La preview es un JPEG dentro de `cache/` y de tamaño ≤ long_side.
- Una exposición +1 aclara la preview.
- 5 renders dejan un solo archivo.
- La foto faltante da "falta el archivo".
- `plan.create` con asset devuelve el draft fusionado.
- `provider:"cloud"` da `INVALID_PARAMS`.
- La miniatura emite `thumbnail.ready` (con un Notifier sobre StringIO y una espera con
  timeout) y la segunda llamada devuelve la ruta directa.
- Los hashes de los originales no cambian.

### Task 4: contrato JSON Schema + tipos TS

**Files:**
- Modify `engine/src/pstudio/__init__.py`: `pstudio schema --rpc`.
- Create `engine/schema/rpc-1.schema.json`, `app/scripts/gen-types.mjs`,
  `app/src/engine/contract.gen.ts`, `app/src/engine/client.ts` y
  `.github/workflows/app.yml`.
- Test `engine/tests/test_rpc_contract.py`.

**Produces:**
- `contract.rpc_json_schema()` devuelve `{title:"Rpc", properties:{"Methods":…, "Events":…},
  $defs}`. Cada método es `{params, result}`.
- En TS: `call<M extends keyof Methods>(method, params)`, `onEngineEvent(name, handler)` y
  `onEngineRestarted(handler)`.
- `test_committed_rpc_schema_is_up_to_date`.
- El CI `app` corre `pnpm gen:types && git diff --exit-code` + `tsc --noEmit`.

### Task 5: Rust (eventos, relanzamiento, assets) y banco de medición

**Files:** Modify `app/src-tauri/src/{engine,lib}.rs`, `Cargo.toml` (feature
`protocol-asset`), `tauri.conf.json` (assetProtocol + CSP `http://asset.localhost`) y
`app/src/App.tsx` (banco RPC que reemplaza al del spike; #57 hace la UI real).

**Produces:**
- `Engine::spawn(python, on_event, on_exit)`.
- Evento `engine-event {method, params}`.
- Relanzamiento con como mucho 3 intentos por minuto, que emite `engine-restarted {attempt}`
  o `engine-failed`.
- Las llamadas pendientes al morir el engine fallan con "el motor se reinició".
- Si `project.open/create` responde bien, se habilita `cache_dir` en el scope de assets.
- En debug, `PSTUDIO_ENGINE_PYTHON` permite usar el venv.
- `cargo test`: un engine falso (python -c) emite una notificación y sale, y se verifica que
  se llaman `on_event` y `on_exit`.
